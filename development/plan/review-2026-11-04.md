## Findings and steps

### 43. Production would run polar-ui v2.1.1 behind upstream's edge-service

`platform/production/polar-ui/resources/polar-ui.yml` pins `ghcr.io/mikkosuonio-ai/polar-ui:v2.1.1`,
but production's edge-service overlay deploys `ghcr.io/polarbookshop/edge-service:latest` from the
book's upstream base (33). That image neither permits nor routes `/media/**`, so v2's self-hosted
fonts get 401, and its catalog fallback is an empty string, which v2's HttpClient parses as null
(32, a spinner for good). Latent: production can't be deployed today (42).

**Step 8:** pin production back to `ghcr.io/polarbookshop/polar-ui:v1`, with a comment why, and
note under 33 that production's polar-ui moves to the fork's image together with the overlays
moving to this repository's edge-service.

### 44. Production's Keycloak realm accepts logins over plain HTTP

Production's `keycloak-config.yml` has `sslRequired: none`, and the Helm values set
`KC_HTTP_ENABLED=true` and `KC_HOSTNAME_STRICT_HTTPS=false` behind a plain HTTP LoadBalancer on
port 80; edge-service's ingress has no TLS either. Passwords, session cookies and tokens cross the
internet unencrypted. Only compose needs `none` (35). Setting `external` alone would lock everyone
out of the login page, since no request reaches Keycloak over HTTPS.

**Step 9:** the realm setting only makes sense with TLS in front of Keycloak and edge-service,
which belongs to the production Keycloak redesign (42) and can't be tried here (no production
cluster). So: record 44 under 42 as a requirement of its fix (TLS at the ingress, for example with
cert-manager, then `sslRequired: external` and without the HTTP-only flags), and put a comment at
the realm setting and in `values.yml` pointing there. If the user prefers, the manifests change now
instead, unverified.

### 45. The browser tests' cleanup deletes every book whose ISBN starts with 97

`removeOwnBooks()` in `development/ui-test/tests/polar.ts` runs
`DELETE FROM book WHERE isbn LIKE '97%'`. Every real ISBN-13 starts with 978 or 979, and the
database is `polar-postgres` of `polar-deployment/docker/docker-compose.yml`, the book's own local
deployment. Running the tests by hand against that stack with real books deletes them.

**Step 1:** the tests mark their books with one author, `Browser Tester`, and the cleanup deletes
only books with both the ISBN prefix and that author. `addBook` and the form tests use a shared
constant.

### 46. order-service's testcontainers-keycloak expects a newer Testcontainers than its BOM

order-service moved to testcontainers-keycloak 3.9.0, built against Testcontainers 1.21, but its
BOM pins 1.19.8, as edge-service's does; catalog pins 1.21.3. It passes today, with mixed versions.
Finding 14 needs 1.21.4 anyway before the runners move to Docker 29.

**Step 7:** `testcontainersVersion` 1.21.4 in catalog-, order- and edge-service. Check the
resolved versions with `dependencies --configuration testRuntimeClasspath`, and run each build
locally under Podman. This does the code part of 14; its runner check stays deferred.

### 47. The findings say the browser tests can run against Kubernetes

`development/findings.md` says under future work that the browser tests "take `UI_BASE_URL`, so
they can run against the cluster too". But their fixtures and outage tests run
`podman exec polar-postgres` and `podman pause catalog-service`.

**Step 6:** correct the note: Kubernetes needs those stack operations behind a helper that uses
kubectl there.

### 48. `withPodman` loses a test's error when the undo fails

In `polar.ts`, an exception from the undo command in `finally` replaces the test's own error, and
the undo note stays in `UI_UNDO_FILE` (the script then runs it once more).

**Step 2:** run the undo in its own try/catch. Remove the note only when the undo succeeded; when
it fails, throw its error only if the test itself succeeded, and otherwise add it to the test's
error.

### 49. `smoke-test.sh test ui` runs the browser tests without edge-service

Without a running edge-service, all ten tests run into their timeouts, about ten minutes, before
failing.

**Step 4:** `test_ui` first checks that edge-service answers `GET /`, and otherwise fails one
check that says so and skips the tests.

### 50. edge-service routes only listed SPA paths (left open)

spa-route and the security config list `/`, `/*.css`, `/*.js`, `/favicon.ico` and `/media/**`. A
polar-ui release that adds files elsewhere, such as `assets/` or Angular's `public/` directory,
gets 401 for them. The browser tests would catch it, since they fail on any response of 400 or
more. Goes to `development/findings.md`.

### 51. `watch-run.sh` can follow a run forever

It hides `gh`'s errors and retries every minute without limit, so with a missing or expired token
it waits silently for good; at the start, the same failure says "No run for … yet".

**Step 5:** print `gh`'s error; tell an authentication failure from a missing run at the start;
give up after 10 failed requests in a row; and take an optional deadline (default 90 minutes,
three times a run's 30-minute job limit).

### 52. The browser tests time out under memory pressure (left open)

`8afafad` records local `all ui` runs passing 99 and 98 of 100 checks, a different test timing out
each time, while the machine stalled with three Claude sessions besides the stack. Goes to
`development/findings.md`, with what to collect next time: the traces of the timed-out tests and
the memory pressure (`/proc/pressure/memory`) during the run.

### 53. The customer test sometimes can't read the order it placed

`03-customer.spec.ts` read the `POST /orders` response's body with `response.json()` after the
click. Since polar-ui v2.1.1's HttpClient uses fetch, Chromium sometimes no longer has that body:
"Protocol error (Network.getResponseBody): No data found for resource with given identifier", in
2 of 8 local repeats (found in step 2's local run; CI's runs passed).

**Step 3:** the test routes `POST /orders` through `route.fetch()` and `route.fulfill()`, and reads
the order from the fetched response in the test itself.
