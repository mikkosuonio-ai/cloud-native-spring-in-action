## High

1. **catalog-service's Kubernetes preStop hook can't run** [static].
   - **Problem:** `catalog-service/k8s/deployment.yml:25-28` runs `sh -c "sleep 5"`, but since 4dc2ae2 the image comes from `builder-noble-java-tiny`, which has no shell. The image has no `ls` either. Boot 3.5's default builder is the same tiny image.
   - **Effect:** every pod termination gives `FailedPreStopHook`, and SIGTERM arrives immediately, so rollouts drop requests.
   - **Fix:** `lifecycle.preStop.sleep.seconds: 5`, which has been GA since Kubernetes 1.34 (MicroK8s here is 1.35).
   - **Caveat:** the staging and production overlays use upstream's `k8s` base (`github.com/polarbookshop/catalog-service/k8s?ref=main`), so a fix here doesn't reach them.
   - Runtime check deferred (D1).

2. **catalog-service: Spring Security 6 applies `anyRequest().hasRole("employee")` to error dispatches** [run]. `SecurityConfig.java:22-26` doesn't permit `/error`.
   - Anonymous `GET /books/` returns 401 with `WWW-Authenticate: Bearer` instead of 404.
   - `GET /books/%` returns 401 instead of 400.
   - **With PostgreSQL stopped, anonymous `GET /books` returns 401 instead of 5xx.** Server outages look like authentication failures to the SPA, to edge-service's circuit breaker and to monitoring. Customers get 403.
   - MockMvc tests don't do error dispatches, so nothing caught it.
   - **Fix:** `.dispatcherTypeMatchers(DispatcherType.ERROR).permitAll()` (or `.requestMatchers("/error").permitAll()`), plus a `RANDOM_PORT` test for `/books/`.

3. **order-service: a failed order-accepted publish leaves an orphaned ACCEPTED order** [static]. Since 81cd148, `submitOrder` isn't `@Transactional`.
   - `StreamBridge.send` is synchronous and throws on broker failure. The Rabbit binder 3.2.10 handler is an `AmqpOutboundEndpoint` with a channel-transacted `RabbitTemplate`.
   - `SimpleR2dbcRepository.save` has already committed by then. The client gets a 500, the order stays ACCEPTED forever, and a retry creates a duplicate. Before 81cd148 the error rolled the save back.
   - Neither the code comment nor findings.md mentions this trade-off.
   - **Fix:** a transactional outbox, or catch the send failure and mark or retry the order. At least document it.
   - Runtime check deferred (D2).

4. **CI is probably red for catalog, order and edge** [likely; can't check here: no remote, no `gh`].
   - GitHub's hosted Ubuntu runners have used Docker Engine 29 since 2026-02-09, which needs API ≥1.44.
   - Testcontainers before 1.21.4 falls back to API 1.32 and fails with "client version 1.32 is too old". catalog pins 1.21.3; order and edge pin 1.19.8.
   - **Fix:** Testcontainers 1.21.4. [run] It works with the local Podman 4.9 (API 1.41): all edge tests passed with it.

## Medium

5. **The `testdata` profile is active by default** [static]. Since 6314b2d, `application.yml:30-31` makes `BookDataLoader` run `deleteAll()` on any start without `SPRING_PROFILES_ACTIVE`, including the README's `java -jar`. bootRun, compose and every Kubernetes overlay set the profile explicitly. **Fix:** remove `spring.profiles.active` from `application.yml`.

6. **Kubernetes liveness restarts during slow starts** (open in findings.md) [static]. All five `k8s/deployment.yml` files have liveness probes with a 10 s delay and 5 s period, and no startupProbe. The kill comes after 20-25 s. **Fix:** a startupProbe (period 5, threshold 30), plus `timeoutSeconds: 3` on liveness for CPU contention.

7. **OTel agent 2.x exports logs by default** [run].
   - With the compose environment, catalog-service (agent 2.20.1) logs "Failed to export logs" every ~10 s. order-service with agent 1.33.3 doesn't export logs (`none` default).
   - The regression is catalog-only. Against a real Tempo it would be UNIMPLEMENTED errors instead. **Fix:** `OTEL_LOGS_EXPORTER=none` in compose and the production patch.
   - The agent version is also hard-coded in the jar path in four places. 4305b66 already fixed one drift.
   - `production/patch-tracing.yml` isn't listed in `production/kustomization.yml`, and the overlay deploys upstream's image (agent 1.33.6). So the in-range edits there have no effect, and if wired in, the JVM would fail to start because the 2.20.1 jar isn't in that image.
   - **Fix:** package the agent under a fixed name, or use the Paketo OpenTelemetry buildpack.

8. **order-service's order-dispatched consumer dies on its first error** (pre-existing; findings.md understates it) [likely].
   - `OrderFunctions.java:20-22` calls `.subscribe()` with no error handling.
   - One database error or optimistic-lock failure ends the stream, so every later order-dispatched event is lost until a restart.
   - **Fix:** per-element `onErrorResume` with a log, or a non-reactive `Consumer` so the binder's retry and DLQ apply.

9. **docker-compose: order-service has no `extra_hosts: host.docker.internal:host-gateway`** [static]. Its JWT issuer uses that host, so on Linux Docker every authenticated `/orders` request fails. catalog and edge got the entry in this range, and `smoke-test.sh:188` hides the gap.

10. **Smoke test vs. concurrent worktrees** [run].
    - Container names, ports, network, image tags, the Kubernetes namespace and the port-forward port are global.
    - podman-compose 1.0.6 recreates a shared service (new container ID) when another worktree's compose file differs. polar-postgres has no volume, so its data goes.
    - **Fix:** take a `flock` and document "one stack per machine". Per-worktree names would be the larger change.

11. **Smoke-test robustness** [run].
    - No curl call has `--max-time`. Against a paused container, curl was still hanging after 20 s.
    - `podman pause catalog-service` (:752) isn't undone by the EXIT trap, so an interrupted run makes the next one hang.
    - `k port-forward … &` backgrounds a shell function, so `$!` is a subshell. Killing it left the child running (reproduced with a mock), so the Keycloak port-forward leaks and holds :38080.
    - `$WORK/body` is reused, so a failed curl can be checked against the previous response and print a misleading PASS.
    - SKILL.md's 10-minute tool timeout can kill a `--rebuild` run midway.

12. **`tempo.yml` is Grafana's demo config** [static].
    - It points at a memcached server compose doesn't define, which fills the logs with errors.
    - It turns on cost attribution, demo retention and the local-blocks processor, which costs memory.
    - It dropped `usage_report.reporting_enabled: false`, and Tempo 2.8 reports usage to Grafana Labs by default.
    - **Fix:** trim it, restore the opt-out, and bind `0.0.0.0:4317/4318`. The explicit endpoint is needed since Tempo 2.7.
